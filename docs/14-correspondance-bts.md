# 14 — Correspondance avec les attendus du BTS SIO SLAM

Cette page aide à comprendre **pourquoi** certaines exigences figurent dans le projet. Elle ne remplace pas les documents officiels ni le tableau de synthèse individuel.

## Conception et développement

Le projet fournit des occasions de démontrer :
- analyse d’un besoin ;
- architecture applicative ;
- modélisation ;
- utilisation d’un framework ;
- développement/adaptation de composants ;
- accès aux données ;
- échanges Web via API ;
- tests ;
- documentation ;
- utilisation d’un environnement de développement.

## Maintenance

L’évolution du mercredi et l’incident du jeudi permettent de produire des preuves de :
- recueil et analyse d’une évolution ;
- mise à jour d’une solution existante ;
- diagnostic ;
- correction ;
- tests de non-régression ;
- mise à jour de la documentation.

## Gestion des données

La base permet de travailler :
- requêtes ;
- conception/adaptation du schéma ;
- contraintes ;
- droits selon l’environnement retenu ;
- déploiement ;
- sauvegarde et restauration.

## Sécurité applicative

Les exigences de cette semaine introduisent :
- habilitations ;
- validation ;
- prévention des injections ;
- protection des secrets ;
- journalisation ;
- analyse d’un comportement anormal ;
- correction et contre-mesure.

## Compétences communes mobilisables dans le portfolio

Selon ce que vous réalisez et documentez réellement, le projet peut également apporter des preuves pour :
- gestion de ressources numériques ;
- réponse aux incidents et demandes d’évolution ;
- évolution d’un site Web exploitant les données de l’organisation ;
- travail en mode projet ;
- tests et déploiement d’un service ;
- accompagnement/documentation utilisateur.

## Principe fondamental

**Une case n’est pas acquise parce qu’un mot apparaît dans le README.**

Pour pouvoir revendiquer une compétence, vous devez être capable de montrer :
1. une action réalisée ;
2. une production ;
3. une preuve ;
4. votre contribution personnelle ;
5. votre capacité à l’expliquer.
