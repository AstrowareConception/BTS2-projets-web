# 02 — Planning du 23 au 27 novembre 2026

Le rythme est volontairement soutenu. Les jalons servent à éviter qu’une mauvaise décision du lundi ne soit découverte le vendredi.

## Lundi 23 — Comprendre, choisir, concevoir

### Matin
- lecture des sujets ;
- choix du contexte ;
- choix et réservation des règles ;
- reformulation du besoin ;
- identification des acteurs et cas d’usage ;
- création du dépôt et du backlog.

### Après-midi
- modèle de données ;
- architecture ;
- maquette basse ou moyenne fidélité ;
- validation de la maquette ;
- initialisation Slim / Composer / connexion BDD.

### Jalon du soir
Vous devez disposer de :
- sujet et combinaison validés ;
- backlog ;
- cahier des charges personnalisé ;
- modèle de données ;
- maquette des écrans principaux ;
- squelette applicatif lançable.

## Mardi 24 — Construire le socle

### Matin
- schéma SQL ;
- authentification ;
- utilisateurs, rôles et habilitations ;
- navigation ;
- premiers repositories/services.

### Après-midi
- fonctionnalités métier essentielles ;
- tableaux/listes utiles ;
- validations serveur ;
- premiers tests.

### Jalon du soir
- authentification fonctionnelle ;
- droits différenciés ;
- base réellement utilisée ;
- au moins un workflow métier complet ;
- commits réguliers.

## Mercredi 25 — Règles métier & API

### Matin
- implémentation des 3 règles contractuelles ;
- tests associés ;
- finalisation du cœur fonctionnel.

### Après-midi
- API REST ;
- consommation/test de l’API ;
- **évolution client imposée** ;
- analyse d’impact avant modification.

### Jalon du soir
- 3 règles contractuelles démontrables ;
- API fonctionnelle ;
- évolution créée dans le backlog ;
- modèle/documentation mis à jour si nécessaire.

## Jeudi 26 — Qualité, sécurité, maintenance

### Matin
- réalisation de l’évolution ;
- tests de non-régression ;
- sécurité ;
- logs ;
- contrôles d’accès.

### Après-midi
- exercice d’incident ;
- diagnostic ;
- correction ;
- test de non-régression ;
- rapport d’incident ;
- travail sur les règles d’extension.

### Jalon du soir
- évolution terminée ;
- incident documenté ;
- application stabilisée ;
- au moins une extension terminée ;
- documentation à jour.

## Vendredi 27 — Livrer et défendre

### Matin
- finalisation des extensions ;
- recette complète ;
- sauvegarde / restauration de BDD ;
- déploiement ;
- correction des derniers défauts.

### Après-midi
- release ;
- documentation ;
- constitution des preuves BTS ;
- démonstration ;
- retour d’expérience.

### Jalon final
Votre projet doit être exécutable, déployé, documenté et démontrable sans bricolage de dernière minute.
