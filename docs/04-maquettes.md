# 04 — Maquettes obligatoires

La maquette fait partie de la conception. Vous ne devez pas attendre que l’application soit terminée pour réfléchir à son interface.

## Outil

Libre : Figma, Penpot, Excalidraw, diagrams.net, papier photographié proprement, ou outil équivalent.

## Écrans minimum

Vous devez maqueter au minimum :

1. accueil / partie publique ;
2. connexion ;
3. tableau de bord ;
4. écran principal du métier ;
5. création ou édition d’un élément important ;
6. écran lié à l’une de vos règles métier ;
7. état d’erreur, refus ou absence de données significatif.

## Ce qui est évalué

La maquette doit montrer :

- hiérarchie de l’information ;
- navigation ;
- actions principales ;
- cohérence des composants ;
- distinction des rôles ;
- retours utilisateur ;
- lisibilité.

## Validation

Avant d’investir du temps dans les vues finales :

1. exportez vos maquettes dans `docs/maquettes/` ;
2. ajoutez un lien vers la source modifiable si elle est en ligne ;
3. vérifiez que chaque cas d’usage principal possède un écran ou un parcours ;
4. demandez la validation.

## Écart maquette / produit

Vous avez le droit de modifier l’interface pendant le développement. Dans ce cas, documentez les écarts importants dans `docs/decisions.md` :

- décision ;
- raison ;
- conséquence.

Le but n’est pas d’être prisonnier de la maquette ; le but est de **concevoir avant de coder et de savoir justifier les évolutions**.
