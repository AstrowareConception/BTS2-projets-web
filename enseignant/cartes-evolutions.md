# Cartes d’évolution — Mercredi

## Principe recommandé

Attribuer à chaque étudiant **une règle non sélectionnée parmi ses règles contractuelles**. Si possible, choisir une règle qui crée un impact sur le modèle ou le workflow.

L’étudiant doit d’abord produire une analyse d’impact dans une issue avant de coder.

## Variante difficile pour un étudiant très avancé

Au lieu d’ajouter simplement la règle :
- modifier une règle existante ;
- préserver les données existantes ;
- exiger une migration ;
- demander une compatibilité API ;
- demander un test de non-régression supplémentaire.
