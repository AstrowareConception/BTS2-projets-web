# 10 — Constituer des preuves exploitables pour le BTS

Votre projet doit laisser des traces exploitables dans votre portfolio et lors d’une soutenance.

## Dossier de preuves recommandé

```text
docs/preuves/
  01-besoin/
  02-maquettes/
  03-modelisation/
  04-regles-metier/
  05-tests/
  06-api/
  07-securite/
  08-maintenance/
  09-deploiement/
```

## Preuves possibles

- cahier des charges ;
- backlog ;
- issues ;
- maquettes ;
- MCD / diagrammes ;
- schéma SQL ;
- extraits de code ciblés ;
- tests ;
- rapport de recette ;
- historique Git ;
- documentation API ;
- captures ;
- rapport d’incident ;
- procédure de déploiement ;
- sauvegarde/restauration ;
- release.

## Compétences particulièrement mobilisables

Cette réalisation peut fournir des preuves sur :
- conception et développement d’une solution applicative ;
- modélisation ;
- utilisation d’un framework ;
- composants d’accès aux données ;
- technologies Web et échanges entre applications ;
- tests ;
- maintenance corrective et évolutive ;
- gestion des données ;
- documentation ;
- sécurité applicative ;
- travail en mode projet ;
- mise à disposition d’un service.

Elle n’a pas vocation à « cocher artificiellement tout le BTS ». Les compétences doivent être justifiables par des actions réellement réalisées.

## Préparer l’oral

Vous devez pouvoir expliquer en quelques minutes :

1. le besoin ;
2. votre architecture ;
3. une règle métier complexe ;
4. une décision de modélisation ;
5. un test ;
6. l’évolution ;
7. l’incident ;
8. le déploiement.

Si vous ne pouvez pas expliquer une partie du code, elle constitue une mauvaise preuve.
