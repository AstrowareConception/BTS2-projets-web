# Grille finale indicative

Cette grille aide à apprécier la réalisation de manière homogène. Elle peut être adaptée selon les contraintes pédagogiques.

| Axe | Points | Attendus |
|---|---:|---|
| Analyse & conception | 15 | besoin, modèle, architecture, maquettes |
| Fonctionnalités métier | 20 | socle cohérent et workflows |
| Règles contractuelles | 15 | 3 règles correctes et démontrables |
| Données | 10 | modèle, requêtes, intégrité |
| API & échanges | 8 | endpoints cohérents et documentés |
| Tests & qualité | 10 | cas pertinents, recette, non-régression |
| Sécurité | 7 | auth, habilitations, validation, secrets, logs |
| Maintenance | 5 | évolution + incident |
| Git & gestion du projet | 4 | historique, issues, release |
| Déploiement & documentation | 4 | reproductibilité, sauvegarde/restauration |
| Maîtrise / démonstration | 2 | explication personnelle |
| **Total** | **100** | |

## Bonus

Les bonus peuvent distinguer une excellente réalisation, mais ne doivent pas masquer un manque sur le socle.

## Plafonds conseillés

Une réalisation peut être plafonnée pédagogiquement si :
- elle ne fonctionne pas ;
- elle est quasi exclusivement CRUD ;
- l’étudiant ne maîtrise pas le code ;
- aucune règle contractuelle sérieuse n’est démontrable ;
- l’historique ne permet pas d’établir une démarche personnelle.
