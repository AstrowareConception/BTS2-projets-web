# Grille de suivi enseignant

Cette grille est un outil de pilotage, pas nécessairement un barème de note.

## Lundi — /20
- besoin compris : 3
- combinaison de règles pertinente : 3
- backlog : 2
- modélisation : 5
- maquettes : 5
- dépôt initialisé proprement : 2

## Mardi — /20
- authentification : 3
- habilitations réelles : 3
- BDD et relations : 4
- architecture : 4
- premier workflow métier : 4
- Git : 2

## Mercredi — /20
- règles contractuelles : 8
- tests : 4
- API : 4
- analyse d’évolution : 4

## Jeudi — /20
- évolution : 6
- non-régression : 3
- diagnostic incident : 4
- correction : 3
- sécurité/logs : 2
- documentation : 2

## Vendredi — /20
- recette : 3
- stabilité : 4
- déploiement : 3
- sauvegarde/restauration : 2
- documentation : 3
- preuves BTS : 2
- démonstration et maîtrise : 3

## Alertes

### Rouge
- pas de dépôt exploitable ;
- pas de modèle ;
- application uniquement CRUD ;
- authentification factice ;
- absence de règles testables ;
- étudiant incapable d’expliquer son code.

### Orange
- fonctionnalités présentes mais non testées ;
- historique Git pauvre ;
- règles métier dans les contrôleurs/vues sans structuration ;
- documentation en retard ;
- application non déployable.

### Vert
- workflow démontrable ;
- règles métier isolées et testées ;
- API cohérente ;
- maintenance documentée ;
- livraison reproductible.
